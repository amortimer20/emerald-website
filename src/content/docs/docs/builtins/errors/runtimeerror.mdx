<p class="reference-facts">Built-in class · Extends <code>Error</code></p>

A `RuntimeError` is what Emerald raises when the program asks for something that cannot be
done: a position outside a list, dividing by zero, a number too large for an `Int`, or any
other error marked **Raises** in these pages.

```emerald
const values = [1, 2]
try {
    print(values[5])
} catch error: RuntimeError {
    print(error.message)     # prints index 5 is outside this list, which has 2 elements
}
```

<Member name="message" returns="String">

What went wrong, in words.

</Member>

Each part of the standard library raises its own kind of `RuntimeError`, so a program can
handle one kind of problem without catching every other:
[`FileError`](../../../library/files/fileerror/),
[`DateTimeError`](../../../library/dates-and-times/datetimeerror/),
[`RegexError`](../../../library/regex/regexerror/),
[`JsonError`](../../../library/json/jsonerror/), and
[`HttpError`](../../../library/http/httperror/). Catching `RuntimeError` catches all of them.
