<p class="reference-facts">Built-in type · Written <code>true</code> or <code>false</code></p>

A `Bool` is one of two values, `true` or `false`. Comparisons give one, and `if` and
`while` need one to decide what to do.

```emerald
const age = 15
const raining = false
const teenager = 13 <= age <= 19      # → true

if teenager and not raining {
    print("Off to the park")
}
```

A condition must be a `Bool`. Emerald has no values that count as true or false on their
own, so `if count` is an error; write what you mean, such as `if count > 0`.

## Operators

| Operator | Meaning | Example |
| --- | --- | --- |
| `and` | Both are true | `true and false` → `false` |
| `or` | At least one is true | `true or false` → `true` |
| `not` | The opposite | `not true` → `false` |
| `==` `!=` | Compare | `true != false` → `true` |

`and` and `or` stop as soon as the answer is known: in `false and ready()`, `ready()` is
never called, and in `true or ready()`, it is not called either. Use this to check that
something is safe before using it, as in `index < items.count and items[index] > 0`.

Emerald writes these operators as words. `!`, `&&`, and `||` are errors that point to
`not`, `and`, and `or`.

Comparisons give a `Bool`, and they can be chained: `0 <= score <= 100` means
`0 <= score and score <= 100`. Two `Bool`s cannot be ordered with `<` or `>`.

## Comparing as methods

`<`, `==`, and a dictionary already compare and look up values. These methods do the same
things by name, which is what a [generic](../../../language/generics/) function calls when it asks
for [`Equatable`](../../traits/equatable/), or [`Hashable`](../../traits/hashable/): an `Bool` counts as
adopting both, so it works wherever one is asked for. In your own code, the operators read better.

<Member name="equals" params="other: Bool" returns="Bool">

Whether this value and `other` are equal, as `==` decides.

```emerald
true.equals(false)   # → false
```

</Member>

<Member name="hash" params="" returns="Int">

A number for the value, the same for equal values, which is how a dictionary or set finds it.
It can change from one run to the next, so never save it or show it to anyone.

```emerald
true.hash() == true.hash()   # → true
```

</Member>
